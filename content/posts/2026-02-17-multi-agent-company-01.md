개발도 하고, 마케팅도 하고, 블로그도 써야 한다. 1인 개발자라면 누구나 공감하는 딜레마다.

본업(소프트웨어/게임 개발)을 하면서 부업으로 1인 기업을 운영하려면 시간이 절대적으로 부족하다. 그래서 AI 에이전트를 "직원"처럼 활용하는 멀티 에이전트 구조를 설계했다.

## 수익 구조 먼저

장기적으로 광고 수익 기반 3개 채널을 운영한다:

- 게임 개발 + 인앱 광고
- 기술 블로그 + AdSense (이 블로그)
- 유튜브/강좌 + 광고

단기 수익보다 점진적으로 완성도를 높이며 수익이 불어나는 구조를 목표로 한다.

핵심 전략은 하나의 작업 → 세 가지 콘텐츠 파이프라인이다.

같은 내용을 세 채널에 재활용한다. 시간 효율이 3배가 된다.

## 에이전트 계층 구조 설계

처음에는 에이전트를 평면적으로 나열했다. "블로그 에이전트, 개발 에이전트, 마케팅 에이전트..." 하지만 금방 문제가 생겼다. 에이전트들이 서로 충돌하거나 같은 작업을 중복으로 처리했다.

실제 회사 조직처럼 계층이 필요했다: CEO → 경영기획실장(CoS) → 개발실장/홍보실장/마케팅실장

경영기획실장(Chief of Staff)이 핵심이다. CEO인 내가 "게임 출시 준비해"라고 하면, CoS가 이걸 구체적 실행 계획으로 변환하고 각 실장에게 배분한다.

## 기술적 고민: 컨텍스트 폭발 문제

해결책: 독립 컨텍스트 + 파일 기반 메시지 패싱

각 에이전트가 별도 Claude Code 세션으로 실행되며, Git 저장소의 파일로 지시/보고를 교환한다.

### 파일 기반 메시지 패싱의 한계

실행 중인 세션은 새 메시지 도착을 자동으로 감지하지 못한다. 결국 사용자(나)가 직접 트리거해줘야 한다. 반자율(semi-autonomous) 구조다.

이 한계를 극복하려면 이벤트 기반 트리거가 필요하다. GitHub Actions가 이 역할을 한다.

## 클라우드로 확장: GitHub Actions

CEO가 이슈를 생성하면, GitHub Actions가 라벨을 보고 해당 에이전트를 자동 실행한다.

진화 경로: 로컬 파일 → GitHub Actions → Claude Code 스킬 → Agent SDK
