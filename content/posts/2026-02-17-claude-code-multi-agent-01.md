1인 개발자가 여러 역할을 동시에 수행하기란 쉽지 않다. AI 에이전트를 `직원`처럼 활용하면 어떨까? 이 시리즈는 Claude Code 기반 멀티 에이전트를 운영하는 과정을 기록한다.

## 1인 개발자의 딜레마

개발도 해야 하고, 마케팅도 해야 하고, 콘텐츠도 만들어야 한다. 하루는 24시간뿐이다.

핵심 문제는 명확하다. **모든 일을 혼자 할 수 없다.** 그렇다고 직원을 고용할 규모도 아니다. 그래서 AI 에이전트를 직원처럼 쓰기로 했다.

## 계층형 에이전트 오케스트레이션

처음에는 에이전트를 평면적으로 나열했다. `블로그 작성 에이전트`, `SEO 에이전트`, `개발 에이전트`... 하지만 곧 문제를 깨달았다. **누가 이들을 조율하지?**

결국 계층 구조가 필요하다는 결론에 도달했다.

### 메인 에이전트

사용자의 의도를 구체적인 실행 계획으로 변환하는 오케스트레이터다. `블로그 좀 활성화해`라고 말하면, 콘텐츠 에이전트에게 캘린더를 짜라고 지시하고, 마케팅 에이전트에게 SEO 전략을 세우라고 지시한다.

### 전문 에이전트

- **개발 에이전트**: 제품 기획, 태스크 분해, 품질 관리, 릴리즈 관리
- **콘텐츠 에이전트**: 콘텐츠 캘린더, 블로그 관리, 영상 기획, 콘텐츠 파이프라인
- **마케팅 에이전트**: SEO, 마케팅, 데이터 분석

### 하위 에이전트

각 전문 에이전트 아래에 실무 에이전트를 둔다. 예를 들어 콘텐츠 에이전트 아래에 블로그 에이전트를 두고, 실제 포스트 작성과 발행을 맡긴다.

## 독립 컨텍스트 + 메시지 패싱

모든 에이전트를 한 세션에서 돌리면 어떻게 될까? 컨텍스트가 폭발한다. 메인 에이전트의 전략 문서, 개발 에이전트의 코드, 콘텐츠 에이전트의 캘린더가 하나의 컨텍스트에 뒤섞이면 성능이 급격히 떨어진다.

해결책은 **독립 컨텍스트 + 메시지 패싱**이다.

- 각 에이전트가 별도의 Claude Code 세션에서 동작한다
- 에이전트마다 `AGENT.md`에 페르소나와 행동 규칙을 정의한다
- 에이전트 간 통신은 파일 기반 메시지 패싱으로 처리한다

```
agents/
├── planning/
│   ├── AGENT.md        # 페르소나 정의
│   ├── inbox/          # 수신 메시지
│   └── outbox/         # 발신 메시지
├── dev/
│   ├── AGENT.md
│   ├── inbox/
│   └── outbox/
└── pr/
    ├── AGENT.md
    ├── inbox/
    └── outbox/
```

사용자가 메인 에이전트의 inbox에 지시를 넣으면, 메인 에이전트가 이를 읽고 실행 계획을 세운다. 그런 다음 각 전문 에이전트의 inbox에 태스크를 넣고, 에이전트는 작업을 완료하면 outbox에 결과를 보고한다. Git 저장소가 메시지 버스 역할을 한다.

## 다음 편 예고
